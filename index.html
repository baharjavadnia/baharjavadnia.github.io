Understand

Frame the problem before drawing it.

Every piece of work starts with an agreed problem statement and the checks that will say it worked.

  • Onboarding, scoped for launch. I framed it as one helpful, efficient path from sign-up to a finished first document, then cut it into shippable tasks, each written in the product's words with screenshots so any engineer could pick one up.
  • Ideas ranked by outcome. I wrote a product-loop skill that turns any area into ten improvement candidates, each written as input, output, outcome and impact. Its first run put onboarding measurement at the top, and that became the next piece of work.
  • Measures set before the build. Before launch I agreed the funnel steps with the team, so we could see where new users stop instead of guessing.

Design

Audit, redesign, then sweat the last pixel.

The strip at the top of this page borrows a pattern I designed and shipped for the Treescribe chat.

  • The AI chat, audited for first-time users. I captured every screen of a full journey at desktop and phone width and logged 24 findings on 15 screens, 4 of them critical, each with a severity and a proposed fix. Hierarchy · spacing · visual noise · plain language
  • One system for the chat. The redesign gave it one heading scale, one spacing rhythm and a distinct look for tasks, questions, cards and results. A sticky strip now shows a document's seven stages, and finished stages fold into it.
  • Iterated in versions, not in place. Onboarding went through nine design versions, the phone layouts through three and the simulation flow through four. Each was prototyped in Claude Design, refined in Figma and released as a versioned export the engineers and agents build from.

Build and ship

I ship it myself, to the team's standard.

TypeScript monorepo: Next.js, React, NestJS and MongoDB, with Claude Code and Codex.

  • 50 pull requests merged since June 2026. Each went through code review and CI before it reached production, and I fix what review finds on the same branch.
  • Full-stack when the design needs it. Information cards in the AI chat took a new message element end to end: the schema, the prompt that makes the model use it, and the expandable card that renders it.
  • The marketing site. I designed it through fourteen prototype rounds that fed the team's build spec, then shipped its legal pages, re-recorded the product clips, made it readable by AI agents and added the share image.
  • The details people feel. Sign-in transitions and loading states, the chat at phone width, and suggested answers on a neutral chip instead of a pre-selected one.
  • Words are part of the build. I wrote the microcopy and voice rules across the interface, the API and the AI's own prompts, so the screens and the model speak with one voice.

Test and measure

Turn ideas into checks, then read the numbers.

I stay on a feature after it ships, until the evidence says it does its job.

  • An onboarding funnel the team can read. I built it into the admin app: six steps from sign-up to a signed agreement, cohorts by date range and the median time to a first document, with internal accounts left out. I added the timestamps the data model was missing so the counts hold up.
  • Marketing analytics, tested before anyone relied on it. I work in GA4, Google Tag Manager and Microsoft Clarity and publish my own Tag Manager events. I tested the analytics playbook step by step on staging, fixed what the test found, kept staff visits out of the numbers and presented the first dashboard to the team.
  • The AI's behaviour, pinned by tests. I wrote chat test cases, signed off the expected behaviour for the end-to-end suite, and ran a question trial across seven invented client businesses, from a sole trader to a large firm.

Design system

Repeated patterns become rules everyone builds from.

  • The operative document style guide. I wrote the canon for the product's document view: colours, type, marks, states and every surface, with tokens checked against Figma. Any change to it needs my approval.
    ink accent status / done rule
  • Semantic tokens over raw colours. I moved the status badges onto semantic status tokens and hold colour choices to WCAG AA contrast.
  • A brand to build on. I designed the Treescribe mark, set the wordmark rules and wrote a nine-chapter brand book.
  • A voice the AI follows. Sentence case everywhere, plain words instead of system terms, and one vocabulary for every state a task can be in.

Automate

If I do it twice, an agent does it the third time.

I work in five parallel workspaces, each with its own coding agent.

  • Eight Claude Code skills the whole team loads.
    • design-translate Retells a diff or a pull request as the user moments it changes, so reviews talk about people, not functions.
    • inspect-design work-save-design edit-design Move a design from a Claude Design canvas into Figma and out as versioned exports that agents read before they build.
    • work-propose The product loop: ten candidates in input, output, outcome and impact, ranked.
    • work-comments work-context edit-exposure The team's comment voice, a clean handover between agent sessions, and a switch that puts a dev instance on a public address.
  • Agents in my pocket. I built a private Telegram bridge to read, answer and voice-message my coding agents from my phone.
  • My own timesheet, rebuilt. A skill reconstructs my day from commits and agent sessions and writes the line for my work log.
